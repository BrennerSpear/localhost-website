localhost / tracks / everydayProposed track
01

Own Your Everyday AI

Make a tool you can run, change and keep using. Improve something that already exists; you don't need to recreate an entire app.

What should win

A useful tool someone can run, understand or adapt themselves: better dictation, local meeting notes, a home interaction or a creative instrument.

Possible sponsor

Variant · subject to agreement

No sponsor-specific product integration is proposed for this track.
Start small // Project seeds

Dictation that gets your names right

Extend an offline dictation app with a ten-term correction list, raw-versus-corrected preview and a way to add a term.

Demo: Read a short script before and after. Let a visitor add a term and try again offline. Start with Handy.

A recording becomes useful local notes

Import audio, transcribe locally, and draft decisions and action items linked to transcript passages. Save editable files in an ordinary folder.

Demo: Open the passage behind a decision, correct the note and reopen the file with networking disabled. Start with FluidAudio (supported Apple hardware) + a local model.

Two more directions +
  • One useful voice control for your home. Add one interaction to a prepared Home Assistant setup: a desk light, timer or virtual switch. Display what it heard and what it did.
  • A creative instrument powered by a local model. Put three useful controls over one working local image workflow. Save outputs with the settings needed to reproduce them.

For a local-only claim, show a prepared offline run. Set up models and hardware before the day; a prerecorded input or virtual device is a useful first version.

localhost / tracks / memoryProposed track
02

An Agent That Knows You

Make remembered context useful, understandable and controllable.

What should win

Useful memory that survives a new session, moves between agents, or can be inspected and corrected by its user.

Proposed tool / sponsor

Cognee · identity and agreement to confirm

Start from a sponsor-tested shared-memory setup. Event access and eligibility remain to be agreed.
Start small // Project seeds

Pick up where your other agent left off

Connect two existing agents to one memory service. Store five approved facts, one decision with its reason and one next step. Add a “resume this project” command.

Demo: Teach agent A why a feature was postponed. A fresh session in agent B recalls the reason and source.

Fix what your agent remembers

Build a memory inbox with three controls: approve, show source and replace. Keep one fact per item and a simple source ledger.

Demo: Change a seeded morning-meeting preference to afternoons; fresh retrieval uses the correction.

Two more directions +
  • What did we decide, and why? Ingest three sample meeting notes. Answer with dated source excerpts, distinguish proposals from decisions and flag conflicting evidence.
  • An assistant that remembers your device's quirks. Combine one manual excerpt with three approved troubleshooting notes. Recall the earlier fix and cite its source. Keep recommendations read-only.

Shared memory needs the same backend and intentional dataset access; separate installations do not automatically share state. Removing or replacing a memory does not erase source files, prior transcripts or every cached copy. Cognee MCP ↗

localhost / tracks / privateProposed track
03

Keep It Private

Make a useful workflow for information people hesitate to send to AI.

What should win

A valuable private workflow, with evidence of what is protected and where the remaining data boundaries are.

Proposed tool / sponsor

Tinfoil · subject to agreement

Use a verifying client or local proxy. Explain parsing, embeddings, storage, logs and external tools as part of the full flow.
Start small // Project seeds

Private meeting notes you can keep

Import a two-minute sample, transcribe it through Tinfoil, summarize it and save editable local Markdown with links to transcript passages.

Demo: Show connection verification, correct a transcription mistake and export the notes. Audio and text model availability need confirmation.

Find the clause in your paperwork

Open one short sample PDF, extract text locally or through Tinfoil, and answer questions with supporting passages.

Demo: Find a cancellation deadline and show its exact passage; refuse a question the document cannot answer. Keep it to retrieval, with no legal conclusions.

Two more directions +
  • Review your week from your own journal. Use seven fictional entries to generate themes and reflection questions linked to their sources. Let the user save or discard the result. No diagnosis or automatic life advice.
  • Search a folder you control. Index twenty text files with local or verified Tinfoil embeddings. Generate a sourced answer and show exactly which snippets left the machine. Confirm the embedding client path first.

Remote confidential inference is still remote computation. Demonstrate verification and the rest of the data flow. Use fictional or public sample records in the demo. Tinfoil security FAQ ↗

localhost / tracks / computeProposed track
04

Build on Shared Compute

Make something useful with Darkbloom inference. Build the workflow around the model: its interface, files, review steps and outputs.

What should win

A useful or surprising application whose core task uses Darkbloom inference. Show why the chosen model and backend suit the task.

Proposed tool / sponsor

Darkbloom · subject to agreement

Models, credits, limits, supported features and event capacity need confirmation. A changed API address alone is a small contribution.
Start small // Project seeds

Help an open-source maintainer clear a backlog

Import twenty public issues and a README. Suggest categories, possible duplicates, missing reproduction steps and draft replies. Let a maintainer approve or correct them.

Demo: Review five issues, explain one duplicate and export accepted drafts. Start with text; automatic posting can wait.

A story machine the whole room can play

Visitors contribute a place, object or sentence. Generate a short branching story, render predefined visual layouts and let the room vote on the next branch.

Demo: Three contributions visibly change the story and produce an exportable zine. Text generation is enough.

Four more directions +
  • Turn a document pile into a decision packet. Extract proposals, dates, costs and open questions from twenty text documents. Link claims to excerpts and export a corrected briefing.
  • Make a confusing public notice usable. Create a plain-language version and checklist. Compare critical dates, addresses and eligibility with the original; keep outputs as drafts for review.
  • Find out which open model can do your job. Run five fixed tasks against one or two available models. Save outputs, failures, elapsed time and reported usage. Reproduce a failure; no load testing.
  • Turn a workshop into a learning pack. Start with a short transcript. Create a sourced glossary, exercise sheet and open-question list. Let a new participant complete one exercise.

Use public or fictional inputs. Darkbloom's About and API material says the coordinator and provider process plaintext; some other pages make stronger claims. Until clarified, use that narrower boundary. About ↗ · API console ↗

Proposed judging

Three common questions, with each sponsor adding its specific integration requirement. A small useful improvement can beat an unfinished general agent.

01 // Working

Does it work on a real task?

Show the workflow and its output. Let someone other than the builder try the intended task.

02 // Useful

Would someone keep using it?

Show the person you built for and the task they can now finish.

03 // Yours

What control does the user gain?

Explain where execution and data live, what dependencies remain, and what users can inspect, change or take with them.

A short submission card

What it does. What runs where. What data leaves. What was built today. How someone else can try it. Demonstrate your strongest privacy or control claim.
